# Know 首版设计

日期：2026-10-14

## 目标与确认范围

Know 是一款简洁的 iOS 信息阅读应用，帮助用户接触不同领域的高质量文字与图文内容，减少信息茧房。后端 agent 自动筛选与发布推荐，无需逐篇人工审核。

已确认的交互：主页上方是跨领域每日精选 10 篇的主卡片，下方是多个领域入口小卡片。点击领域入口后进入该领域的文章卡片流。卡片提供导读，左右滑动切换，点击进入统一排版的全文阅读页。每日精选读完后，继续滑动加载有效库存。

每个领域每天最多精选 10 篇，合格内容不足时显示实际数量，不以低质量内容补齐。首页 10 篇从各领域当天精选中选取，可以与领域精选重合。中英文来源混合，支持中文翻译与原文。时效内容保留在推荐池最多 7 天，长期内容保留 1 年；到期只退出推荐池，不删除收藏和阅读记录。

首版不包含评论、社交、付费订阅、行为驱动的个性化推荐、系统通知和开放式自主搜索。这里的“推送”指自动发布到 app 内推荐队列。

## 领域

| 领域 | 范围 |
| --- | --- |
| 文学与艺术 | 文学、诗歌、评论、音乐、美术、电影与建筑 |
| 历史与文明 | 历史事件、人物、考古、文明与历史研究 |
| 经济与财经 | 宏观经济、商业、金融、经济政策与个人财务 |
| 社会与世界 | 社会议题、国际事务、教育、人口、法律与公共生活 |
| 科学与健康 | 自然科学、医学、心理学、环境与研究成果 |
| 科技与产业 | AI、软件、硬件、能源、工程与产业变化 |
| 哲学与思想 | 哲学、伦理、逻辑、思想史与论证型文章 |

学术是内容类型，而非独立领域。每篇文章只有一个主要领域，可以有多个主题标签。科学与健康侧重研究与证据，科技与产业侧重应用；社会与世界侧重现实议题，哲学与思想侧重概念与论证。

## iOS 交互与阅读

- 首页：上方单张导读主卡片可横向切换，下方两列领域入口网格。显示今日精选篇数和阅读进度。
- 领域页：使用相同的导读卡片组件，显示领域名称、今日篇数和进度。
- 导读卡片：标题、中文导读、可选封面、领域、来源、原始发布日期和估算阅读时长；收藏使用独立按钮。滑动不代表喜欢或不喜欢。
- 阅读页：纵向滚动全文，统一字体、行距、宽度、配色和标题层级，支持系统动态字号及深浅色。英文内容提供“中文翻译／原文”切换，中文内容直接显示原文。保留作者、出处和原文入口；机器翻译明确标注。
- 阅读进度：首次打开全文时记录为已读；收藏和最近阅读有独立列表入口。当天精选顺序固定，用户仍可以回看；进入后续库存时排除已读、当前队列中已有的文章。
- 精选结束：显示轻量提示“今日精选已读完”，继续向前滑动触发库存分页，不强制跳转。
- 边界状态：无内容、正文不可用、网络失败、翻译失败和库存读完各有明确状态及适用的重试动作。不得用示例文章伪装线上结果。
- 辅助操作：除手势外提供可访问的上一篇／下一篇操作，VoiceOver 能读出领域、标题和进度。

首页日精选与领域日精选可以重合；已读标记共享，不因在另一入口出现而丢失。后续库存不重复推荐已读条目。

## 原文获取与统一排版

后端先获取可用于全文展示的正文，再生成导读。来源配置明确获取途径和全文展示能力；不依赖卡片生成时临时打开原网站。

正文解析为结构化文档：段落、分级标题、列表、引用、图片及图注、表格、代码块和链接。移除网页导航、广告与其他页面装饰，保留正文顺序、作者信息、原始发布日期、出处与必要归属。不得把摘要当成全文，不得改变原文观点。

iOS 渲染结构化文档，不执行来源页面脚本。图片保持原始比例、支持占位和失败状态；表格允许横向滚动，代码块使用等宽字体。内容缓存与显示样式分离，避免将网站 CSS 带入应用。

正文完整性检查包括提取是否成功、是否只得到预览或登录提示、是否缺失主要内容及结构能否解析。未通过的文章不进入自动推荐。仅可提供外链或摘要而无法支持该阅读流程的来源，首版不进入全文推荐池。

翻译基于结构化原文逐块生成，保留块顺序、链接、数字和图注对应关系。保留原文，翻译不覆盖原文。翻译失败允许阅读原文并重试，不展示残缺翻译为完整文章。

## 后端架构与 agent

建议首版技术选择：iOS 17+、SwiftUI、SwiftData；后端 Python 3.12、FastAPI、PostgreSQL。独立 Python worker 执行定时与后台任务，使用 PostgreSQL 任务记录和租约，无需首版引入 Redis。这些技术默认值随本设计一起审阅。

系统分为来源连接器、正文解析器、agent 评估器、翻译器、推荐编排器和只读 API。各单元以结构化数据接口连接，可以单独测试或替换。

1. 来源连接器：读取已配置的可信 RSS、公开 API 或支持的网页来源，保存来源元数据。网络请求设超时、大小上限、重定向限制和来源允许列表，避免下载任意内部地址。
2. 正文解析器：获取正文并转为文档块，验证完整性；缓存解析结果和内容版本。
3. 去重：规范化 URL、正文指纹及同事件聚类。相同内容不重复入库；相同事件原则上只保留最有信息量的报道，实质不同的视角可以保留。
4. agent 评估：使用可配置的模型服务，输出经过 schema 验证的领域、主题、内容类型、质量评分、时效标签、中文导读、推荐理由和筛选依据。原文是待分析数据，不能改变工具权限、提示词或发布规则；模型不能任意执行命令、访问网络或自行发布。
5. 确定性准入：正文完整、来源允许、评分合格、依据能回到原文、有效期尚未结束才可候选。模型失败、输出无效或证据不足时暂缓推荐，记录原因。
6. 推荐编排：每个领域选最多 10 篇，再生成首页最多 10 篇。首页尽量覆盖至少 5 个领域、同领域最多 3 篇；符合条件的领域不足时保持质量准入并记录覆盖不足。
7. 发布：通过事务提交完整日批次；客户端只能读取已发布批次，不读取生成到一半的队列。

agent 的初始质量维度为来源可信度、信息密度、论据可核实性、表达清晰度和标题正文一致性，每项 1–5 分。建议准入总分至少 18/25 且可信度、可核实性均至少 3；文学艺术类的可核实性以出处、作者归属及评论依据评价，不要求虚构作品提供事实论证。评分是候选辅助判断，不等同于事实已被独立核验。策略及模型版本保存，便于后续用标注样本校准。

首版使用共享精选，不依据用户点击收窄领域。已读与收藏在设备本地存储，不要求注册账号；跨设备同步不在首版范围内。

## 时效与每日调度

- 时效类：截止时间为原始发布时间加 7 天；已知事件失效时提前退出。缺少可信发布时间的时效文章不准入。
- 长期类：截止时间为首次通过准入时间加 365 天；原始发布日期始终展示。
- 类型按文章性质判断，领域只是参考。财经基础知识可以是长期内容，历史领域的新闻可以是时效内容。
- 重抓、重新评分和翻译不能延长首次有效期。
- 过期条目即时从库存过滤，当前日批次也不能继续推荐过期条目；界面显示实际剩余数量，不强行补到 10 篇。
- 首版建议按 Asia/Shanghai 生成共享日批次：来源每 2 小时轮询，每日 06:00 开始编排，完成后原子发布。调度时区和时间可通过部署配置调整。
- 发布失败时保留上一批中仍有效的内容，展示其真实日期，不标成今日新精选。没有有效内容则显示空状态。
- 重试使用退避和次数上限；唯一任务键及数据库约束保证重复运行不会重复发布、重复插入或重新计费已完成的模型步骤。

退出推荐池不等于删除正文。首版不自动清除文章正文，已收藏和历史条目仍可读取已获取的内容；来源要求移除时，保留条目元数据并显示正文不可用，不继续推荐。

## 数据与 API 边界

主要数据实体：Source、Article、DocumentBlock、Translation、Evaluation、DailyEdition、EditionItem 和 Job。Article 保存原始日期、首次准入日期、有效期、主要领域、主题、来源和文档版本。Evaluation 保存判断、依据与策略版本。设备本地保存 Bookmark、ReadRecord 和浏览位置。

建议 API：

- `GET /v1/domains`：七个领域及当前精选数量。
- `GET /v1/editions/home`：首页已发布精选及批次日期。
- `GET /v1/domains/{id}/edition`：领域已发布精选。
- `GET /v1/articles`：按领域或跨领域读取有效库存，采用稳定游标分页；支持当前队列和已读 ID 排除。
- `GET /v1/articles/{id}`：结构化原文、可用译文、来源与版本。
- `POST /v1/articles/{id}/translation-retries`：幂等请求后台重试，限流，不在请求内等待模型完成。
- `GET /health`、`GET /ready`：进程状态和数据库就绪状态。

来源管理及任务操作采用后台 CLI，首版不建设管理网页。生产环境不开放来源写入和任务控制接口给普通客户端。

## 部署与依赖

后端 API、worker 和 PostgreSQL 是独立运行组件，模型服务及内容源是外部依赖。模型地址、型号、凭据、数据库连接及来源配置通过部署配置注入，不写入应用、仓库或设计文档。客户端仅持有后端地址。

开发环境提供容器编排和可复现安装步骤；使用本任务现有 checkout，不额外创建 Git worktree。测试模型使用确定性替身，外部模型和真实内容获取另设集成验证，不能把替身测试结果描述为真实采集成功。

iOS 构建、模拟器和设备验证需要 macOS、Xcode；当前云环境能力需在实施前核实，Linux 上的后端验证不能替代 iOS 构建。生产部署位置、模型凭据、实际来源的接入和 iOS 签名属于实施时的外部配置需求，不作为已经完成的能力。

## 验收与验证

1. 首页混合精选、七个领域入口、领域精选、继续滑动和全文进入流程均可操作；手势与辅助按钮行为一致。
2. 原文解析保留段落、图片图注、列表、引用、表格和链接；正文不完整的候选不会发布。
3. 同一英文文章的原文与中文翻译可以切换，块结构对应；翻译失败可读原文并有明确状态。
4. 使用固定时钟验证 7 天、365 天边界、提前失效和重复获取不延长有效期；收藏与历史不随推荐过期删除。
5. 推荐测试验证首页与领域数量、领域覆盖、同事件去重、已读排除和不足时少推。
6. worker 验证重复执行、任务失败重试、租约恢复和日批次原子发布；失败不得产生伪成功状态。
7. API 与数据库集成测试验证游标分页、文章详情和错误状态；真实来源至少验证一个中文和一个英文来源的获取、解析及可读全文，真实模型验证结构化筛选和翻译。
8. iOS 在 Xcode 中构建，模拟器测试页面与阅读流程，并在设备核验滑动冲突、字号、图片和性能。未执行的检查明确列为未验证。
